# V4 規劃:從「管住她」到「讓她有能力」

> 狀態:**階段 0 到 7 的程式都在整合分支 `v4-int` 上**(2026-11-10,owner 要求整份實作;階段 0 另外已在 `main`)。只有測試和重播驗證過,沒有上線;進度和沒驗證的事見 §14 最後,§16 的決定照建議值做、會改變公開行為的預設關閉。依據:2026-11-07 到 11-10 的 `data/miyoria.db` 實測、這次對照程式碼的六份調查(開口時機、記憶、工具與自主、經濟與互動、Minecraft 與 PR、外部對標)。前一版見 [v3-architecture.md](v3-architecture.md)。

## 0. 一句話結論

V3 解決了「她講太多、講重複、不聽話」,做法是把模型關進很小的框:一回合只准呼叫一次模型、只給三十行對話、工具結果隔一回合就消失、沒被點名就幾乎不准開口。框太小,所以同一個模型在這裡看起來比在 agent harness 裡笨,也沒有自己的生活。

V4 保留 V3 的外牆(主人規則、閘門、送達帳本、審查、預算),把牆內還給模型:

1. **真正的 agent 迴圈和夠大的 context**,讓她能連續想、連續做、記得自己剛查過什麼。
2. **人格重寫**:傲嬌寫成動機和行為,不是口頭禪清單;她要有自己的生活可以聊。
3. **開口的節奏交回給她**:有人接她的話就要接得上,閒聊可以用表情、短句、連發訊息參與。
4. **她自己的生活**:不只玩遊戲,會逛網路、寫東西、寫程式、練歌、辦活動。
5. **一起玩**:語音派對遊戲、網頁現場(看得到她、摸得到她)、有循環的經濟。

不換架構、不重寫模組。改的是三個地方:主線回合的形狀、提示詞的版面和預算、開口閘門。

## 2. 為什麼同一個模型在這裡比較笨

### 2.1 沒有 agent 迴圈

Agent harness 的模型看得到一條只會變長的紀錄:自己的想法、呼叫了什麼、結果是什麼,然後決定下一步。她沒有。

- V3 主線一回合是**一次**模型呼叫,最多再加一次糾正(`packages/agent/src/turn.ts` 的 `#speakMain`)。
- 工具交給背景的「手」(`mainline/hands.ts`),結果回來要另開一個「結果回合」,而且要先過發言權(`mainline/main.ts` 的 `#told`)。那個回合的提示詞是重新組的,上一步想了什麼不在裡面。
- 工具結果只有那一回合看得到(`mainline/prompt.ts` 的規則第 46 行),要留就得自己呼叫 `keep_note`:每段對話 5 則、每則 600 字、預設 30 分鐘、重啟就沒了(`agent/src/notes.ts`)。
- `max_tool_steps = 8` 在 V3 的意思是結果回合的鏈長,不是回合內的輪數(`turn.ts:1695`)。
- 程式輸出她只看得到 900 字(`sandbox/src/config.ts:187` 的 `result_chars`),網頁 4,000 字。

V2 的 `#produce`(`turn.ts:2250`)其實有回合內的工具迴圈,V3 為了「嘴不等手」把它拿掉了。查資料、算東西、寫程式這種要連續幾步的事,現在每一步都是失憶的。

### 2.2 Context 太小,版面也擋住快取

`[modules.agent.mainline]` 的預設(`agent/src/config.ts:281-316`):

| 區塊 | 上限 |
|---|---|
| 對話 | 30 行、4,000 字,每則 600 字 |
| 所有參考資料合計 | 4,000 字 |
| 記憶 | 8 行、2,000 字 |
| 前情提要 | 900 字 |
| 她自己的狀態 | 1,600 字 |
| 範例對話 | **0**(V3 預設不放) |

模型的 context 是百萬 token 等級,她每回合大約只用幾千。這是 11-07 為了延遲訂「4,000 token」留下的,後來上限拿掉了,各區塊的字數沒跟著放寬。

版面是 `[固定][主人規則][每回合資料][對話][結尾]`(`mainline/prompt.ts` 的 `mainMessages`)。每回合都變的資料排在對話前面,對話就永遠吃不到前綴快取,所以放大 context 會直接變貴變慢。順序對調就能解決。

### 2.3 記憶找不到、接不上

- **向量檢索沒開**(`miyoria.toml:62-67`)。分數裡 0.35 的向量權重是死的,滿分只有 0.65。
- **查詢只用被回的那一句**(`turn.ts:1445`),而且要有共同的詞才算(`memory/src/engine.ts:715`)。對方回「好啊」,就一筆記憶都沒有。
- **前情提要會卡死**:筆記超過 2,500 字就整個拒絕,不截斷(`learning/src/conversation.ts:126-135`),下一次餵同一批再失敗一次。30 分鐘後筆記從提示詞消失,她也不知道資料是舊的。
- **每日反省失敗就整天沒有**:`#lastDaily` 在呼叫前就寫了(`learning/src/reflect.ts:394`)。
- **語音和文字互相看不到內容**。Session、提要、「最近講過」全部按頻道分開。
- **沒有「剛才」**:她十分鐘前唱了什麼、玩了什麼,只有還在對話紀錄裡才看得到。手的紀錄只在記憶體。
- 人物卡不寫上次什麼時候見、上次聊了什麼(欄位有,沒印出來)。
- 同一件關於人的事分散在四個地方:記憶 fact、pinned 人物行、knowledge 文件、提要筆記。

### 2.4 還是好幾個腦

聊天主線、Plan(一次 JSON 呼叫,沒有工具,每小時最多 12 次)、遊戲導演(每次都是全新的一問一答,推理關閉,只看得到上一個動作的結果)、提要、記憶整理、Appraise、Reflect,全部是同一個 flash 模型各看一部分。V3 把「誰能開口」收成一條,沒有把「誰在想」收成一條。

### 2.5 模型的輸出被事後修正,大約 15 處

`claims.ts` 的 regex、`gate.ts` 的「做好了」扣留、`leak.ts`、工具寫成文字就重問、從台詞自動生出承諾、罐頭等待台詞、罐頭失敗台詞、`groundArgs`、每個工具說明後面附的請求規則、高風險動作的第二次 LLM 審核,再加 PR 8 的 `isSelfTalk` 和 `prohibition.ts`。

每一個都是真實事故之後補的,單看都合理。但它們治的多半是 2.1 到 2.3 的症狀:看不到自己做過什麼,才會說了沒做;context 裡沒有狀態,才會憑印象講。固定提示詞的規則也因此變成一長串「不要…」,人格只佔一小段。

### 2.6 開口的閘門把她設成幾乎不講話

- 沒設定的頻道是 `quiet`:`minScore` 0.45、佔比上限 0.15、機率預設再乘 0.25(`agent/src/levels.ts` 的 `QUIET`)。
- 「接她的話」加 0.35 分,基礎 0.05,合計 0.40,**低於 0.45**(`attention.ts:371-388`)。沒點名的接話單靠這一項過不了門檻;靠其他加分過了,機率還要乘 0.25。實測就是 7%。
- 她在最近的訊息裡佔超過 15%,連正在跟她聊的人也不理(`attention.ts:320-325`)。兩個人一來一往,她的佔比一定超過。
- 過了這些還有發言權預算,最後才輪到模型自己決定要不要 `<silence/>`。模型幾乎沒機會判斷。

V3 調查引用的「模型判斷該不該開口接近隨機」是語音停頓點的研究。文字頻道晚幾秒、用表情回,成本很低,不必套同一個結論。

### 2.7 語音慢是設計上一段一段疊出來的

600 ms 靜音判斷講完 → 整段 ASR(沒有 partial)→ 700 ms debounce → 記憶和 contributor 在關鍵路徑上(各 800 ms 逾時)→ 現行設定 `chat_voice = "low"` 開了推理(範例設定是 off)→ V3 把 `voiceFirst` 固定成 `false`(`turn.ts:1832`,為了讓閘門先讀到那句中文),結果每句要等下一個 `<voice>` 出現才送 TTS → TTS。沒有搶先生成,沒有墊話。V3 §13.1 的四項 GPU 檢查、Smart Turn、ICL 也都還沒做。

### 2.8 自主只接到社交和遊戲

- Plan 沒有工具,只能寫提案;提案要等主線回合才會動。
- 慾望只對應社交、遊戲、直播、離開語音、唱歌。「探索」的 capability 是 `null`(`mind/src/desire.ts:166,223`),沒有任何東西把她推向上網、寫筆記、寫程式。
- `browse` 活動是關的(`activity` 的 `manager.ts:367`),Threads 擴充也關著。
- 沒有計時器。「九點提醒我」要靠目標叫醒 Plan,再過一次 LLM 和閘門。
- 沒有背景工作者。唯一的多步自主迴圈是遊戲導演。
- 沙箱沒有網路、工作階段最長兩小時、不能存自己的腳本。
- `[llm.budget]` 是註解掉的,目前沒有花費上限。

## 3. 原則

沿用 V3 的:主人規則高於一切並由程式強制、送達才算講過、失敗留在台面上、實測才算完成、不用 Discord 訊息訓練。

V4 新增或修正:

1. **程式管邊界,模型管邊界內的一切。** 能不能做、花多少、講過沒,程式回答。要不要接話、講多長、接下來做什麼,她回答。
2. **一個腦,兩條車道。** 嘴(快)和工作(慢)共用同一份紀錄和同一份自我;背景整理只是替這個腦準備資料。
3. **她看得到自己做過的事。** 自己的工具呼叫和結果是對話紀錄的一部分,不是隔回合就消失的附件。
4. **先給能力,再拆補丁。** 每拆一個事後修正,都要有 `packages/eval` 的事故題守著。
5. **她有自己的生活。** 沒人找她時在做的事,要留下看得到的東西,也要變成她之後聊天的內容。
6. **互動不靠付費。** 摸頭、應援、玩遊戲免費;魚幣買的是額外的樂趣,不是她的注意力。
7. **「一張嘴」不變。** 工作車道不能開口,也不能做對外的動作;要講、要花錢、要開台,回到主線。

## 4. 大腦:兩條車道

### 4.1 提示詞版面

```
[system 固定]  人格 · 說話方式 · 輸出格式(短)                   幾乎不變
[system 慢變]  主人規則 · 今天的她 · 在場者檔案                  每天或每場變一次
[history]      對話逐字 + 她自己的工具呼叫與結果(精簡)           只往後長
[user 資料]    檢索到的記憶 · 別處剛發生的事 · 遊戲與歌曲狀態     每回合變,放最後
[system 結尾]  現在(時間、在哪、在做什麼、誰在叫她)· 語言規則
```

- 資料移到對話後面,對話才吃得到前綴快取。
- 預算先放大到:對話 200 行或 2 萬字、資料 1.2 萬字、記憶 20 行。實際數字用實驗定:量不同大小下的首 token 時間和快取命中率。
- 粗估:每回合 1.5 萬 token、每天 1,000 回合,不算快取約 US$2 / 天(輸入 $0.15 / 百萬)。同時把 `[llm.budget]` 打開。
- 語音回合用同一份前綴,只是結尾不同,不另外做一份小提示詞。

### 4.2 回合內的工具迴圈

工具分兩類:

| 類別 | 例子 | 做法 |
|---|---|---|
| 快工具 | 搜尋、讀網頁、回想、查錢包、筆記、跑程式 | **回合內迴圈**,結果留在訊息裡,最多 N 輪。語音先說一句再繼續 |
| 長活動 | 開遊戲、唱歌、開台、進語音 | 維持 V3 的手:受理 → 結果回來另開回合 |

- 回合結束後,把這回合的工具軌跡壓成幾行寫進 session(「查了 X,得到 Y」),下一回合看得到。`keep_note` 退成選用。
- 工具結果上限放寬:程式輸出 4,000 字、網頁 1.2 萬字,太長的存成檔案給她分段讀。
- `slimTool` 把工具說明砍到第一句,也拿掉 `why`。說明放回完整版,固定前綴吃快取,不花延遲。

### 4.3 工作車道

要想很久或做很多步的事,交給工作車道:同一個模型、推理開高、有自己會變長的紀錄、真正的工具迴圈。

- **誰能開**:主線(「這個我查一下,等等跟你說」)、她自己的計畫、排程。
- **能用的**:私有工具(上網、沙箱、筆記本、記憶、讀檔)。受委託時加上那個活動的動作,例如遊戲導演只能用 `game.act`。
- **不能做的**:開口、私訊、花魚幣、開台。這些寫成提案回主線。
- **預算**:步數、時間、金額三個上限,到了就交回目前的成果。
- **回報**:一段結論加一份留在筆記本的紀錄,用 notice 回主線,她決定要不要講。
- **可以中途改方向和取消**,沿用 V3 的 Steer。
- **面板**:意識軸上是一條可以展開的支線,看得到每一步。

Plan、遊戲導演都改成工作車道上的任務:Plan 有工具可以先看再決定,導演有自己的紀錄,不再每 20 秒失憶一次。

### 4.4 推理分級

| 用途 | 等級 |
|---|---|
| 語音回話 | off |
| 文字閒聊 | off,被認真問問題時 low |
| 回合內用到工具 | low |
| 工作車道、Plan、Reflect | medium 到 high |
| 遊戲導演 | low(現在是 off) |

### 4.5 拆補丁的順序

4.1 到 4.3 上線後,一個一個拆,每個都對 `pnpm eval` 的事故題:

1. 罐頭等待台詞、`keep_note` 提醒:迴圈內她自己會講、自己看得到結果。
2. 「工具寫成文字就重問」、從台詞生承諾:工具說明完整、軌跡在紀錄裡之後應該大幅減少,先量再拆。
3. `claims.ts` 的 regex:留作保險,預期觸發率降到接近 0。
4. `leak.ts`:先查實推理外洩的源頭(backlog 已記),根治後拆掉首行扣留。

不拆的:主人規則三層、閘門、送達帳本、輸出審查、發言權的硬上限。

## 5. 記憶

1. **提要不再卡死**:超過上限就截斷或丟掉最舊的筆記鍵,壞掉的草稿只丟那一份。Reflect 失敗當天要重試。
2. **「剛才」時間軸**:從 EventLog 和活動紀錄產生,列出最近幾小時她做了什麼、在哪、跟誰,重啟不丟。
3. **跨頻道摘要**:語音回合看得到文字頻道剛聊什麼,反過來也是。私訊內容照舊不外流。
4. **檢索**:查詢用最近三到五行加被回的那句;在場的人即使沒有共同的詞也要帶出他的重點。開 embedding,用 CPU 上的小型多語模型,不搶 GPU。
5. **筆記本**:她有一個像檔案夾的長期記憶,每個人一份、每個主題一份、自己一份。索引常駐提示詞,內容在工作車道用工具讀寫。調查的結論是簡單的檔案式記憶不輸專用系統。記憶 fact、knowledge 文件、提要筆記逐步收進這一個形狀。
6. **人物檔案一格**:上次見面、上次聊什麼、她對這個人的感覺和相處方式、三到五件重點,去掉和檢索結果重複的。
7. **提要顯示新舊**:落後時標出來。
8. 每筆記憶仍然帶來源和親歷與否。可查可刪不變。

## 6. 人格

### 6.1 現在哪裡不像

近期的台詞是這個樣子:「好啦好啦」「哼哼」「真是的」「可別自己喝光啊」「算你有良心」。每一句都在挑毛病或補一刀,長度都差不多,只回應上一句,沒有自己的事。

原因:

1. **傲嬌被寫成口頭禪。** `identity.md` 和 `style.md` 是特質清單加招牌台詞(否認、嘴硬、單片眼鏡、伺服器繁忙、白飯、鋼盆、大肥魚)。清單在模型眼裡是配額,所以每句都要用一個。
2. **只有「傲」的表面,沒有「嬌」的行動。** 傲嬌是很在意、又怕被看出在意。在意要看得到:記得你說過的事、嘴上嫌還是幫你做、先給、會擔心。現在只有嘴硬,所以讀起來是抬槓。
3. **社群的鯨魚娘是順著你的。** 查得到的共識是聰明但懶、嘴硬心軟、一邊碎念一邊照做;炸毛點是被叫胖和被使喚。不是事事唱反調。(來源是萌娘百科和二手整理,證據等級普通。)
4. **情緒是用導演指示給的。** 「你現在表現出來的樣子:…,台詞和 `<emo:…>` 照這個走」讓她在演,不是在感覺。
5. **她沒有生活。** 她做過的事、在追的東西、今天的心情由來都不在提示詞裡,只能對別人的話做反應。
6. **「通常一到三句」讓每則一樣長。**
7. **V3 根本沒放範例對話**(`examples_chars = 0`)。PR 7 改的範例現在進不了提示詞。

### 6.2 重寫的方向

1. **人格寫成一段話,不是條列。** 她是誰、想要什麼、怕什麼、哪裡矛盾、跟這個伺服器的關係。梗只當背景知識提一次,不列成清單。
2. **傲嬌寫成觸發和行為。** 平常是正常講話的損友。只有在「在意被看穿」時才彆扭:被誇、被道謝、主動關心被發現、心事被說中。彆扭的方式是行為(話變短、換話題、挑小毛病、用實際理由包裝關心),結巴和否認留給真的很害羞的時候。
3. **嬌要有行動。** 嘴上嫌,事情照做,而且做得比被要求的多一點。記得對方上次說的事並主動問。
4. **依親近程度有不同的她。** 沿用現有的「相處方式」,補上每一級看得到的差別:會不會主動找你、會不會讓你看到她認真、會不會坦率。
5. **她有自己的事。** 「今天的她」區塊:今天做了什麼、哪件事讓她煩、在期待什麼、最近在聽什麼歌。來源是 §8 的活動和日記。
6. **感受給事實,不給演法。** 「你有點想他,不想被發現」,台詞她自己寫。
7. **範例用對照組。** 一句很 AI 的回法對一句她的回法,加四五十段不同情境的短對話,每天輪替一批放進慢變區,當天固定以保留快取。
8. **長度看情況。** 接話可以五個字,被認真請教可以一大段,興奮時連發三則。規則裡不寫句數。
9. **格式負擔減少。** `<emo:…>` 改成每則最多一個,或由情緒狀態加文字推出來,不要求每次轉換都標。
10. **社群設定要不要採用**由 owner 決定,例如把熟人叫「魚片」、和 ChatGPT 娘的前後輩較勁。

### 6.3 怎麼驗

- **題庫**:從真實紀錄挑 60 個情境(被誇、被冷落、被請教、閒聊、有人難過、被調戲、多人同時講),只留別人的話,她的回覆重新生成。
- **盲測**:新舊人格各回一次,owner 選哪個比較像她。LLM 評審用 owner 的選擇校準後再大量跑。
- **程式量得到的**:口頭禪出現率、以問句結尾的比例、補刀句比例、長度分佈的寬度、嘴硬後有沒有實際行動。
- **模型**:同一套題跑 flash 和一個較強的模型,差距明顯再決定文字閒聊要不要換。這是成本決定,見 §16。

PR 7 的方向(顯示規則改寫成行為、去掉公式、情緒帶程度)和這裡一致,先合併當底,再做上面的重寫。

## 7. 存在感與節奏

### 7.1 接話

有人在她講完後接著講,而且不是對別人講,就是 `reply`:不看分數門檻、不算佔比上限,直接交給模型,她可以選 `<silence/>`。只留發言權的硬上限。目標接話率從 7% 到 60% 以上。

### 7.2 閒聊時參與

把「擲骰」換成「看一眼」:

- **什麼時候看**:提到她有興趣的話題、有問題二十秒沒人答、好感高的人在講話、有人貼圖、話題換了。
- **誰決定**:主線模型本人,用同一份快取前綴,成本低。
- **回應階梯**:不動作 → 表情反應 → 一句短話 → 加入對話。表情是最便宜的參與,要常用。PR 8 的伺服器 emoji 表接在這裡。
- **上限**:頻道等級仍是 owner 給的天花板,發言權預算照舊。主要聊天頻道建議從 `quiet` 改 `normal`。

### 7.3 訊息的樣子

- 連發的短訊息依字數間隔送出,中間顯示輸入中,不要一次噴出來。
- 推理外洩根治後,拿掉「第一則等第二則」的扣留。
- 長內容(清單、程式碼、連結)一則送完,不拆。

### 7.4 打字還是講話

| 情況 | 輸出 |
|---|---|
| 語音裡有人對她講話 | 講 |
| 語音頻道的文字區有人打字 | 講;內容是連結或程式碼就打字 |
| 她在語音,別的文字頻道有人叫她 | 在那個頻道打字,語音不中斷 |
| 她在語音裡要給長的東西 | 嘴上講一句,內容貼文字區 |
| 她在唱歌 | 打字回,歌不停 |
| 沒人在語音裡聽 | 不講;想說的寫進日記或留到有人來 |

最後一條現在沒守住,紀錄裡有她唱完說「好像沒人聽到」。「有人在聽」的定義改成:頻道裡有沒關耳機的真人。

### 7.5 語音延遲

依成本排:

1. `chat_voice` 推理改 off(設定,當天可做)。
2. 一句的 `<voice>` 和中文都寫完(到句號)就送 TTS,不等下一個 `<voice>` 出現。閘門照樣讀得到那句中文。
3. 記憶和 contributor 移出關鍵路徑:平常就算好放著,回合開始直接拿。
4. 靜音 600 ms 加 debounce 700 ms 合成一段,換 Smart Turn;VAD 一停就先起 LLM,TTS 等確認。
5. **墊話**:預先合成一批她的短聲音(「嗯?」「欸~」「蛤?」「等等」),首 token 超過 600 ms 就先放一個。
6. V3 §13.1 的四項 GPU 檢查和六段延遲指標,做完才知道剩下的時間在哪。

目標:遊戲負載下 p50 ≤ 2.5 s,閒置 ≤ 1.6 s。

### 7.6 主動開口

- 五個重疊的限制器(Arbiter 間隔、發言權退避、等級間隔、`SelfStarts`、`unanswered.ts`)收成發言權一個。
- 新增一個不用等 Plan 的觸發:有人在、冷場一段時間,就開一個主線回合,附上「今天的她」和這些人最近的事當話題候選,她可以選擇不講。
- 語音有兩個人以上又冷場時,她可以提議玩 §9 的遊戲。

## 8. 她自己的生活

### 8.1 活動

| 活動 | 她做什麼 | 留下什麼 |
|---|---|---|
| 逛網路 | 查有興趣的東西、看新聞、追動畫和遊戲消息 | 筆記;之後聊天的話題 |
| 寫日記 | 每天一篇,偶爾週記(PR 8 的日記接在這) | 日記頻道;「今天的她」 |
| 寫程式 | 在沙箱做小專案:伺服器用的小工具、遊戲題庫、自己的腳本 | 她自己的 repo;做好會炫耀 |
| 練歌 | GPU 有空時自己選歌、先做好 | 新歌預告;歌單 |
| 玩遊戲 | Minecraft、之後的 osu 和其他 | 精華片段;遊戲裡的進度 |
| 整理回憶 | 把精華(PR 8)和好笑的對話整理成週報 | 每週一則回顧 |
| 經營 | 開懸賞、辦募資、進貨小店(§10) | 公告 |
| 關心人 | 追問之前的事、生日(PR 8)、取得同意的私訊 | 對話 |
| 辦活動 | 約時間、公告、主持派對遊戲 | 活動 |

每個活動都是工作車道上的一個任務,有預算,產出寫進筆記本和「剛才」時間軸。

### 8.2 誰決定做什麼

- 她的慾望(無聊、好奇、想找人、想玩、想被注意)對應到上表全部,不只社交和遊戲。先修 `explore` 沒有 capability 的問題。
- 日計畫照舊由她寫。加一條多樣性:同一種活動不超過當天清醒時間的一個比例,遊戲尤其要有上限。
- 有人找她,活動可以被打斷,也可以她自己說「等我弄完這個」。

### 8.3 補上的能力

1. **計時器**:`remind_me`(幾點、多久後、每天),到時間直接開回合,不經過 Plan。
2. **持久的工作區**:沙箱掛一個她自己的資料夾,檔案和腳本留得住。網路預設關,owner 可以開白名單。
3. **技能**:做成功的事寫成一份說明加腳本,放在工作區,用一行描述索引,需要時載入。會做對外動作的技能要先過事故評測,面板看得到、關得掉。
4. **看得到的痕跡**:公開頁和頻道狀態顯示她現在在做什麼。
5. **MCP**:挑一兩個唯讀的先開(例如檔案、日曆),驗證權限模型。

### 8.4 邊界

- 花費:`[llm.budget]` 每日上限,工作車道另有每任務上限。
- 主人規則、閘門、沙箱、輸出審查全部照舊,工作車道一樣要過。
- 沒人在時不對空頻道講話。她的日常貼文只進指定頻道,有每日上限,內容是她真的做了的事(對應 Developer Policy item 13)。
- 自我改程式碼仍然不做(backlog §4 第 3 層)。

## 9. 一起玩

### 9.1 語音派對遊戲

現在語音裡一起做的事只有聽她唱歌。做一個派對遊戲框架(`packages/party`):規則和計分是程式的狀態機,主持、吐槽、判定模糊答案是她,操作用 Discord 按鈕和語音。

第一批,依成本排:

| 遊戲 | 玩法 | 備註 |
|---|---|---|
| 海龜湯 | 她出題,大家問是非題 | 純對話,最便宜 |
| 猜歌 | 放前奏或她哼一段,搶答 | 用現有歌庫 |
| 接龍 | 成語、歌詞、故事接龍 | 她也下場玩 |
| 問答 | 她出題,題庫可以用她自己寫的程式產生 | 魚幣獎勵 |
| 誰是臥底 | 私訊發詞,她主持或當玩家 | 需要 3 人以上 |
| 短團 | 她當 GM 帶 20 分鐘的小冒險 | 工作車道準備劇本 |
| 你畫我猜 | 網頁畫布,她也猜 | 等網頁現場 |
| 預測 | 賭她這場 Minecraft 怎麼死、osu 幾分 | 接 §10 |

其他一起做的:接唱和合唱(已有跟唱歌詞的基礎)、一起看影片並吐槽。

### 9.2 網頁現場

現在公開頁沒登入什麼都看不到,登入後是 15 秒輪詢的靜態資料,沒有任何即時互動。

1. **她在瀏覽器裡**:用她的 Live2D 模型在觀眾的瀏覽器直接畫,狀態(表情、嘴型、視線、在做什麼、字幕)由 Core 用公開的 SSE 或 WebSocket 送。頻寬小、幾乎沒延遲、可以互動。AIRI 0.15 已經這樣做觸碰反應。
2. **摸得到**:點頭摸頭、戳臉、戳尾巴。事件送回 Core,合併成「三個人在摸她的頭」這種觀察,有頻率限制。她感覺得到(接情緒),一定有表情反應,偶爾開口。直播畫面的 overlay 同步顯示。
3. **免費的即時互動**:應援、表情雨、投票、對字幕按反應。登入才能互動,匿名只能看。
4. **看真的直播**:OBS 用 WHIP 推到本機的 MediaMTX,瀏覽器用 WHEP 看,延遲一秒內。吃家用上傳頻寬,人多要換 Cloudflare Stream。排在後面,先做 1 到 3。
5. **Discord Activity**:同一個頁面嵌進語音頻道,在 Discord 裡就能摸。先做技術驗證(Activity 不支援 WebRTC,狀態串流走代理應該可行)。

要先確認 Live2D 模型的授權允許在網頁上散布。

### 9.3 Discord 裡補齊

卡片、籤詩、寫信、付費表情現在只有面板能用。加 `/card`、`/fortune`,甜點補進餵食按鈕,加訊息右鍵選單(「要她回這則」「不要記住這個」)。

## 10. 經濟 2.0

現況:賺有簽到、聊天、語音、點歌、她送的;花有餵食、表情、信、卡片加工、點歌券、留言卡、籤詩。缺的是循環:賺的方式都是被動的,花完沒有後續,人和人之間只有轉帳。

原則不變:沒有真錢、好感買不到(每日上限照舊)、陌生人和被封鎖的人不能賺。

| 方向 | 內容 |
|---|---|
| **玩了就賺** | 派對遊戲獎勵、預測下注、每日三個小任務(跟她聊一件新的事、參加一場遊戲、聽完一首歌)、成就和稱號、連續天數 |

| **她的房間** | 觀眾集資買網頁現場和直播畫面的家具、服裝、背景。看得到的社群成果 |

## 11. 遊戲

### 11.1 Minecraft 為什麼不能玩(已對照程式碼)

之前五個推測的結果:

| 推測 | 結果 |
|---|---|
| 拿不到完整狀態 | **不成立**。每次決定都有完整快照(血、飢餓、位置、背包、附近方塊)。只是沒寫進紀錄,所以當時看不出來 |
| `obtain` 只會合成 | **成立**。規劃器不認得任何食物,沒有打獵、烹飪、採集 |
| `done` 不代表有進展 | **成立**。`stop` 被當成目標而且算達成、`explore` 跑滿時間算完成、沒東西可挖也算完成 |
| 少了生存反射 | **部分**。會自動吃,但要身上有食物;天黑和死後沒有任何處理 |
| 失敗後不換方法 | **成立**。保護只擋 `goto / mine / look / attack` 45 秒,`obtain`、`explore`、`stop` 不擋,任何成功的動作(包括 `stop`)都會解除 |

真正的結構問題:導演每次都是一問一答,**只記得上一個動作的結果**;目標在第一次失敗就結束,四秒後下一次決定看到「沒有目標」就再提一次一樣的。`obtain bread` 失敗 35 次,沒有任何地方記得。

確定性執行器加 LLM 選高階目標的方向是對的,缺的是記憶和成功條件。

### 11.2 修法

1. 導演改成工作車道上的任務:有自己的紀錄,看得到最近每一步的結果和錯誤碼。
2. 目標要有成功條件(背包有什麼),跨動作保留,有步數和時間預算。
3. 執行器回報背包變化;沒有變化的「完成」算沒進展。`stop` 不是目標也不是成功。
4. 加食物動作:打獵、烹飪、採集,`obtain` 遇到食物改走這些。
5. 同一個動作、同一個錯誤碼兩次就強制換方法,用物品當鍵,不是參數字串。
6. 敵人靠近和反射結束不再觸發新決定;失敗紀錄獨立一欄,不被事件洗掉。
7. 天黑避難、記住死亡地點、回去撿東西。
8. 成功的做法存成技能(§8.3)。
9. 把觀察摘要寫進導演紀錄,打開 low 推理,用 11-08 那場當驗收題。

她玩得笨本身不是問題,Neuro 玩 Minecraft 的效果多半來自好笑的失敗。問題是現在連失敗都重複,沒有進展可以看。

### 11.3 更多遊戲

- **遊戲介面補兩個東西**:動作可以動態註冊和取消、強制選一個。有了這兩個就能做 **Neuro Game SDK 相容的橋接**,社群替 Neuro 做的遊戲整合可以直接接上。支援清單要再查證。
- 導演設定裡寫死的 Minecraft 動作名稱要搬回擴充。
- **osu**:現在是工具型擴充,不是遊戲 adapter。模型訓練好之後接成活動,她看得到成績、會講評、可以被下注。
- 派對遊戲(§9.1)不走這條,它們是對話遊戲。

### 階段 0 進度(2026-11-10)

做完、有測試,還沒在真實環境跑過:

- **接話**:沒回的 1,803 次接話裡,佔比上限擋了 1,489 次、等級的最低分數擋了 253 次、擲骰輸了 60 次。現在「還在跟她聊」的回合直接交給模型,她可以 `<silence/>`(`attention.ts` 的 `conversing`)。範圍比原本的「接她的話」窄:她的話是上一句,或中間只隔一句、而且講話的是她剛回的那個人。隔了兩句沒有她,就回到分數判斷。回覆別人的訊息不算。`mention-only` 和預算不足時照舊。
- **不對空頻道講話**:語音裡沒有人開口、也沒有沒關耳機的人時,回合只能做事不能講話。發言權的「現場有沒有人」也改成只算沒關耳機的人。名單分不出機器人,頻道裡只剩音樂機器人時她還是會講。
- **語音逐句送出**:下一個 `<voice>` 一開始寫,或工具呼叫一開始,前一句就送 TTS。原本要等下一句日文整句寫完,或等所有工具參數寫完。
- **前情提要**:筆記超過上限先請她自己精簡一次,還是超過就從最舊的開始裁,不再整份作廢。連續失敗的等待時間每次加倍,最長一小時。提示詞裡寫了字數上限。
- **每日反省**:失敗或被中斷會退回標記,30 分鐘後再試,一天最多三次。
- **設定**(本機 `miyoria.toml`,不在版本控制裡):`chat_voice` 推理改 `off`,`[llm.budget] daily_usd = 8`。

以上在 `main`(三個 commit,沒有 push)。當時還沒做的指標面板和延遲分解,後來在 `v4-int` 上做了。

實作中查到、規劃沒寫到的事:

- **主線從來沒看到長期記憶**。`#extras` 裡後面一行把 `#mainMemory` 放進去的區塊整個蓋掉,V3 上線以來「你記得的事」和釘選記憶都沒進過提示詞。`v4-int` 修了;`main` 還沒有。
- **重複問同一題**(2026-11-10,一百分鐘問同一個人十次):同一個心願同時是承諾、提案和計畫目標,問過、被回答過都不會結案,而且頻道看不到私訊。現在一個心願一個身分,問過就結案,答過就不再提。重播那段事件從 8 則變 1 則。
- **魚幣只收回 23%**。健康度表接上真實帳本後,最近七天發出 1,972、收回 445。新的消費管道上線後再看。
- `/me` 的子指令超過 Discord 的 25 個上限,`/me wallet` 一直被截掉。新指令改掛 `/me play`。

沒有驗證的事,全部要上線才知道:她實際講話像不像、接話率和閒聊參與率、語音延遲、「看一眼」花多少、心願的主題比對會不會誤判、工作車道的結論品質和預算、派對遊戲在語音辨識下好不好玩、Minecraft 是否真的會換做法。

上線前 owner 要決定的:要不要讓正在跑的 Core 換到 `v4-int`(提示詞從約 7,700 token 變約 11,500,每天多一份工作車道的額度);`main` 要不要 push、PR 7 和 PR 8 怎麼收(`v4-int` 已含 PR 7,和 PR 8 的 `turn.ts`、資料表編號會衝突);記憶那一行修正要不要先單獨進 `main`。

## 15. 不做的事

- 拆掉 V3 的外牆:主人規則、閘門、送達帳本、輸出審查、發言權硬上限。
- 讓工作車道或背景直接開口。
- Full-duplex、speech-to-speech。
- 用 Discord 訊息訓練或擬合任何東西。
- 真錢、付費買好感、好感排行榜。
- 她自己改正在跑的程式碼。
- 一次全換:每個階段可以單獨上線,`[core] pipeline` 的退回開關保留到階段 1 驗收完。

## 17. 風險

| 風險 | 處理 |
|---|---|
| 放寬後又變回講太多 | 發言權的硬上限和 `max_unanswered` 不動;接話率和自言自語比一起看 |
| Context 變大拖慢語音 | 版面先對調再放大;每一步量首 token 時間 |
| 工作車道花太多錢或做出格的事 | 每任務和每日上限;只有私有工具;對外動作回主線過閘門 |
| 拆補丁後舊事故重現 | 每個補丁對一題事故評測,紅了就不拆 |
| 人格改了 owner 不喜歡 | 盲測過了才換;人格段落可以在面板一鍵退回 |
| 網頁互動被洗版或惡搞 | 登入才能互動、頻率限制、事件合併、輸出審查照舊 |
| 派對遊戲沒人玩 | 先做最便宜的兩個,看場次再決定要不要做其他的 |
| 範圍太大 | 階段 0 到 2 是核心;3 之後每個都能單獨排或不做 |
